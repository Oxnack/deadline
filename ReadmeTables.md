# ReadmeTables.md

## Структура данных MVP «Супермаркеты»

Все таблицы в формате CSV лежат в папке `data/`.  
**Первичный ключ** выделен жирным в каждой таблице.

---

## 1. users.csv — профили пользователей

| Столбец | Тип | Описание |
|---|---|---|
| **user_id** | string | Уникальный ID пользователя |
| age | int | Возраст, лет |
| gender | string | M или F |
| city | string | Город проживания |
| income_rub | int | Среднемесячный доход, руб |
| family_status | string | один / пара / семья_с_детьми / с_родителями |
| created_at | datetime | Дата создания записи |

**Как заполнять:** один раз при регистрации пользователя в экосистеме.  
Доход обновлять раз в месяц из зарплатных зачислений.

---

## 2. transactions.csv — банковские транзакции

| Столбец | Тип | Описание |
|---|---|---|
| **transaction_id** | string | Уникальный ID транзакции |
| user_id | string | FK → users.user_id |
| timestamp | datetime | Дата и время покупки |
| amount_rub | float | Сумма в рублях |
| merchant_name | string | Название магазина |
| merchant_type | string | эконом / средний / премиум / онлайн |
| city | string | Город совершения покупки |

**Как заполнять:** автоматически из банковского ядра.  
Одна строка = одна транзакция по карте.  
Обновляется в реальном времени или раз в сутки батчом.

---

## 3. app_events.csv — действия внутри приложения

| Столбец | Тип | Описание |
|---|---|---|
| **event_id** | string | Уникальный ID события |
| user_id | string | FK → users.user_id |
| session_id | string | ID сессии (объединяет события одного захода) |
| timestamp | datetime | Время события |
| event_type | string | Тип действия (см. список ниже) |
| source | string | Откуда пришёл: push / organic / email |

**Типы событий (event_type):**

| Значение | Смысл |
|---|---|
| app_opened | Открыл приложение |
| category_viewed | Посмотрел категорию товаров |
| search_query | Ввёл поисковый запрос |
| product_clicked | Нажал на карточку товара |
| cart_updated | Добавил/удалил товар из корзины |
| order_started | Начал оформление заказа |
| order_completed | Оплатил заказ |
| order_cancelled | Отменил заказ |
| push_received | Получил пуш-уведомление |
| push_clicked | Кликнул по пушу |

**Как заполнять:** автоматически — приложение отправляет событие на бэкенд через API.  
Пишется в реальном времени (event streaming) или логом.

---

## 4. orders.csv — заказы в Супермаркетах

| Столбец | Тип | Описание |
|---|---|---|
| **order_id** | string | Уникальный ID заказа |
| user_id | string | FK → users.user_id |
| event_id | string | FK → app_events.event_id (событие order_completed) |
| timestamp | datetime | Дата и время заказа |
| amount_rub | float | Сумма заказа |
| is_first_order | int | 1 = первый заказ пользователя, иначе 0 |
| delivery_minutes | int | Время доставки в минутах |

**Как заполнять:** одна строка при каждом успешном `order_completed`.  
Связка с `app_events` через `event_id`.

---

## 5. user_embeddings.csv — векторные представления пользователей

| Столбец | Тип | Описание |
|---|---|---|
| **user_id** | string | FK → users.user_id |
| segment | string | Категория: family / budget / gourmet_solo / busy_pro / traditional |
| family_score | float | Вероятность принадлежности к family |
| budget_score | float | Вероятность принадлежности к budget |
| gourmet_score | float | Вероятность принадлежности к gourmet_solo |
| busy_score | float | Вероятность принадлежности к busy_pro |
| traditional_score | float | Вероятность принадлежности к traditional |
| churn_risk | float | Риск оттока 0–1 (не вернётся в течение 30 дней) |
| predicted_ltv | float | Предсказанная пожизненная ценность, руб |
| updated_at | datetime | Когда последний раз пересчитывались эмбеддинги |

**Как заполнять:** пересчитывается периодически (раз в сутки или неделю) скриптом, который:
1. Забирает свежие данные из `transactions`, `app_events`, `orders`
2. Агрегирует фичи (средний чек, частоту, доли по типам магазинов)
3. Прогоняет через LightGBM-модель
4. Записывает вероятности в эту таблицу

**ВАЖНО:** при создании таблицы все значения нулевые/пустые.  
Заполняются первым прогоном скоринга.
